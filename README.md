# GD Passrate Tracker

**Версия 1.32.0** · Windows · macOS · Linux

Трекер статистики для гринда уровней Geometry Dash. Пока ты пытаешься пройти
уровень, он считает: какой кусок валит сильнее всего, как быстро растёт твой
скилл, сколько попыток и фуллов уже влито. Прогрессы вбиваются руками по одной
строке, вставляются целым столбиком — или вообще не вводятся: если стоит мод
Death Tracker (Geode), каждая смерть попадает в статистику сама.

Всё хранится только на твоём компьютере: без сети, без аккаунтов, без
телеметрии. Интерфейс аккуратно перестраивается на узких окнах и телефонах.

![Основной экран трекера](screenshots/main.png)

Что умеет — коротко:

- **Считает пассрейт** каждой части уровня и общий пассрейт — обновляется
  сразу после каждой попытки.
- **Делит уровень на части по стартпосам** и красит карту уровня от красного
  к зелёному — с одного взгляда видно, где умираешь.
- **Рисует графики роста**: общий пассрейт, пассрейт по частям, скорость
  роста и прогноз, когда рост выйдет на плато.
- **Видит запуски игры**: попытки группируются по игровым сессиям — «сколько
  в среднем прохожу за вечер».
- **Синхронизируется с модом Death Tracker** — при живой синхронизации
  трекер не нужен вообще: умираешь в игре, запись появляется сама.
- **Помнит всё**: журнал попыток с правками, «Отменить» до 50 шагов, заметки
  по уровню, экспорт отчёта в `.md` / `.txt` / `.json`.

## Что такое пассрейт?

Пассрейт — доля попыток, которые проехали отрезок уровня целиком. Если часть
уровня проходится 12 раз из 40 заходов, её пассрейт — 30%. Это вся теория.

Трекер делит уровень на части по стартовым позициям и считает две главные
цифры:

- **Пассрейт части** — «как часто я прохожу этот кусок». Отвечает на вопрос,
  какая часть валит.
- **Общий пассрейт уровня** — «шанс доехать с нуля до 100% за одну попытку».

Общий пассрейт — произведение пассрейтов всех частей, потому что для фулла
нужно пройти все части подряд. На пальцах: 4 части, каждая проходится в 60%
случаев → 0,6 × 0,6 × 0,6 × 0,6 ≈ **13%**. Не 60%, а 13 — и это не ошибка
трекера, а честная математика: слабое звено рушит произведение на порядок.
Именно поэтому одна сложная часть способна обрушить общий пассрейт почти
в ноль, даже когда всё остальное проходится на отлично.

Кому-то этого хватает, но трекер на этом не останавливается: поверх расчёта
строятся модели сравнения, средние прохождения за сессию, динамика роста и
тренировочный режим Blitzkrieg — обо всём этом ниже.

## Быстрый старт за пять шагов

### 1. Поставь Node.js

Приложение запускается через Node.js — это просто «движок», качается один раз
с [nodejs.org](https://nodejs.org). Бери версию **LTS** (18, 20 или новее).
Установка — «далее, далее, готово». Проверить, что встало: открой терминал и
выполни `node -v` — должна показаться версия.

### 2. Распакуй архив

Распакуй архив в **новую пустую папку**. Не поверх старой версии трекера —
старые файлы мешают и приводят к странным ошибкам (см. [FAQ](#если-что-то-пошло-не-так)).
Готовая сборка уже внутри архива, ничего собирать не нужно.

### 3. Установи и запусти

Открой терминал в папке с распакованным архивом и выполни две команды:

```bash
npm install              # один раз: качает зависимости (~1–2 минуты)
npm run electron:start   # запускает приложение
```

Откроется окно трекера — тёмное, неоновое, в стиле GD. Закрыть приложение —
просто закрой окно; запускать потом той же командой `npm run electron:start`
(или ярлыком, если создашь `.bat`/скрипт с ней).

> Если `npm install` падает на скачивании — обычно это медленный GitHub.
> Просто повтори команду, она докачает. Помогает и зеркало:
> `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install`.

### 4. Создай сеанс уровня

Нажми «+» в панели сверху, придумай имя (например, `Sonic Wave`) и укажи
стартовые позиции: `5, 10, 25, 50, 75` — через что угодно, запятые, пробелы,
переводы строк. Лень перечислять — жми «Сгенерировать равные части».

### 5. Вводи прогрессы

Умер на 63%? Введи `63` и Enter. Всё. Дальше трекер сам: счётчики, пассрейты,
карта, графики — всё пересчитывается мгновенно после каждой попытки.

> Хочешь, чтобы попытки вводились **сами** при смерти в игре? Поставь мод
> [Death Tracker](https://geode-sdk.org/mods/elohmrow.death_tracker/) и
> настрой синхронизацию —
> [это одна панель и пара минут](#автосинхронизация-с-death-tracker-geode).

## Как вводить попытки

Поле «Новая попытка» понимает три формы — все как ты привык записывать:

| Вводишь | Что это значит |
|---|---|
| `63` | попытка с нуля, умер на 63% |
| `30-100` | ран со стартпоса 30% до конца |
| `40 x3` (или `40 ×3`, `40 *3`) | три одинаковые попытки подряд |
| `62,5` | дробный прогресс — запятая или точка |

Правила простые. Конец — не больше 100. Старт — либо 0, либо один из твоих
стартпосов: стартовать «из середины части» нельзя, поле подсветит ошибку.
Ошибся — жми «Отменить»: трекер помнит последние 50 действий и откатит всё
как было, включая неудачный импорт и сброс.

Формат круглый: всё, что выводится кнопкой «Копировать» из журнала,
вставляется обратно через «Импорт» без вопросов. Так статистика переносится
между сеансами и компьютерами — выгрузил на одном, вставил на другом.

## Возможности

### Сеансы уровней

Один сеанс — один уровень, со своей разбивкой на части и статистикой. Сеансов
веди сколько хочешь параллельно: чипы уровней вверху с текущим общим пассрейтом,
переключение одним кликом. Активный уровень запоминается — при запуске
откроется последний, за которым ты сидел. Правка — карандашом, удаление — с
подтверждением в два клика (первый «взводит» кнопку, второй удаляет — случайно
нажать не выйдет).

### Разбивка уровня на части

Части — это отрезки между стартпосами: в GD новая попытка стартует либо с
нуля, либо со стартовой позиции, поэтому границы частей — ровно те точки,
откуда бывают старты. Вводи стартпосы как удобно: `5, 10, 25, 50, 75` —
запятые, точки с запятой, пробелы и переводы строк в любых комбинациях,
дробные через точку (`62.5`). Дубликаты и значения вне 0–100 убираются сами.

Поменял разбивку с теми же границами — статистика останется. Если границы
сдвинулись, трекер честно предупредит: части пересоздадутся, счётчики
обнулятся, журнал попыток сохранится.

### Журнал попыток и «Отменить»

Каждый ввод попадает в журнал — хронологический столбик всех попыток: что
введено, когда, откуда старт. Опечатка не приговор: кнопка правки развернёт
запись обратно в поле, кнопка удаления уберёт её — счётчики пересчитаются
точно, а не «примерно». Внизу — сводка «N записей · M попыток» и кнопка
«Копировать»: выгружает журнал текстом с итогами, готовым к переносу.

Кнопка «Отменить» откатывает последнее действие целиком — ввод, импорт,
правку, удаление, даже сброс. «Сбросить» обнуляет счётчики и журнал сеанса
(с подтверждением), но не трогает заметки.

### Импорт столбиком

![Импорт из столбика: предпросмотр разбора, счётчик распознанного](screenshots/import.png)

Кнопка «Импорт» — для ленивых и для переносов. Вставь в поле список попыток
столбиком (`63`, `30-100 x5`, `62.5` — по одной на строку) или перетащи
готовый `.txt` прямо в поле. Перед применением покажется предпросмотр:
сколько записей распознано, сколько попыток, и список строк с ошибками —
пока не исправишь, ничего не применится. Строки-комментарии, начинающиеся
с `#` или `//`, пропускаются: можно вставлять целые сохранённые отчёты.

Весь импорт — одно действие: одна «Отмена» откатит его целиком, сколько бы
строк там ни было.

### Группировка прогрессов

Под журналом — компактная сводка повторов: «9% ×3, 18% ×2, 32% ×1 …».
Каждая строка — прогресс, сколько раз он повторился, и полоска-гистограмма
относительно самого частого. Ввод `9, 9, 9` и запись `9 ×3` дадут одну
группу «9% ×5». Обновляется мгновенно, сразу видно, на каком проценте
«сидишь».

### Статистика уровня

![Общий пассрейт, средний и медианный на часть, модели, участки](screenshots/passrate-models.png)

Центральная колонка — цифры, ради которых всё затевалось:

- **Общий пассрейт** — крупное неоновое число: шанс пройти весь уровень за
  одну попытку с нуля. Рядом — попытки, фуллы и число частей.
- **Средний пассрейт на часть** — «насколько части проходятся по отдельности».
  Произведение убивает одна сложная часть, среднее почти не трогает: разрыв
  между ними и показывает, насколько уровень неровный.
- **Медианный пассрейт на часть** — пассрейт «типичной» части. Среднее
  чувствительно к выбросам (одна аномально лёгкая часть тянет его вверх),
  медиана — нет. Среднее заметно ниже медианы — уровень портят несколько
  очень сложных частей; выше — есть неестественно лёгкие.
- **Шанс доехать до 50% и 70%** — тот же расчёт, но для начала уровня:
  полезно, когда фулл пока за облаками.
- **Модели 50/60/70/80%** — «а каким был бы общий пассрейт, если бы каждая
  часть проходилась одинаково». Сравнение показывает: у тебя уровень ровнее
  «эталона» (ранние легче, финал сложнее — как обычно и бывает) или наоборот.

Пустые части показываются честным нулём: если часть не заходили ни разу,
трекер не притворяется, что данных достаточно.

### Карта уровня и карточки частей

![Карта уровня: цвет части — её пассрейт; карточки частей со счётчиками](screenshots/level-map.png)

Горизонтальная полоса 0–100%, где ширина каждого блока — длина части, а цвет —
её пассрейт: от красного к зелёному. Это наглядный ответ на «какая часть
валит»: даже не читая цифры, видно красное пятно, на котором ты застрял.
Под картой — карточка каждой части: диапазон, сколько раз зашёл, сколько
прошёл, пассрейт с цветной полосой. Это единственное место, где видны и
абсолютные числа, и доли одновременно — удобно сверяться с калькулятором,
если не верится.

### Графики динамики

![Модалка «Динамика пассрейта»: пять графиков роста](screenshots/dynamics.png)

Кнопка «Графики динамики» открывает окно с пятью графиками:

1. **Общий пассрейт во времени** — как рос (и падал) шанс пройти уровень.
   Пунктиром можно наложить модель 50/60/70/80% для сравнения.
2. **Пассрейт по частям** — линии для выбранных частей: выбирай чипами,
   какие показывать, остальные не мешаются.
3. **Скорость роста** — сколько процентных пунктов в день прибавлял пассрейт.
   Бывает отрицательной — неудачные серии честно показываются красным.
   Чип «Сглаживание ×5» убирает шум отдельных дней.
4. **Скорость по частям** — какая часть «дорастает» быстрее; над графиком
   рейтинг, лидер подсвечен.
5. **Ускорение** — рост разгоняется или выдыхается.

Отдельная строка — **прогноз плато**: если скорость роста снижается, трекер
прикидывает дату, когда рост почти остановится («≈ 01.10.26, через ~8 дней»).
Это экстраполяция текущего темпа, а не обещание — но «гринд выдыхается, пора
менять подход» видно заранее.

Вся динамика восстанавливается из журнала попыток: каждая запись хранит
время, поэтому графики работают и по старой статистике. Наведение на точку
показывает дату, саму попытку и значения всех рядов.

### Игровые сессии и окно сессии

![Панель «Игровые сессии»: запуски игры с длительностями и записями](screenshots/game-sessions.png)

Трекер сам видит, когда Geometry Dash запустился и закрылся — в шапке
тикающий бейдж «Игра запущена · 12 мин», в панели слева — список запусков с
длительностью и числом записей. Каждая попытка попадает в сессию по времени
ввода: вручную ничего группировать не нужно.

Зачем это нужно:

- **«Сколько я в среднем прохожу за вечер»** — средние прохождения частей
  (0–50%, 0–61%, 0–70%+) считаются по игровым сессиям: доехал от нуля до
  отметки — засчитано, стартпос-раны не считаются.
- **Окно сессии** — клик по строке показывает все прогрессы того запуска
  по **всем уровням сразу**: чипы повторов и полный список со временем.
  Сортировка — четырьмя кнопками: время туда-обратно или прогресс 100→0 /
  0→100.

![Окно игровой сессии: все прогрессы одного запуска игры по всем уровням](screenshots/session-window.png)

Окно живое: пока оно открыто, новые записи появляются в нём сразу, а
длительность текущей сессии тикает. Если трекер стоял закрытым, а игра
успела перезапуститься — старая сессия закроется, откроется новая, ничего
не склеится.

### Автосинхронизация с Death Tracker (Geode)

Лучший режим: вообще не трогать трекер во время гринда. Мод
[Death Tracker](https://geode-sdk.org/mods/elohmrow.death_tracker/)
(v2.x, автор elohmrow) пишет статистику каждого уровня в файл и обновляет
его на каждую смерть — трекер следит за этими файлами и применяет события
сам: умер три раза между сканами, получишь одну запись `63 ×3`, а не три.

Настройка один раз, панель «Death Tracker» слева:

1. **Выбрать папку сейвов мода** — кнопкой с диалогом или «найти
   автоматически». Обычно это
   `%LOCALAPPDATA%\GeometryDash\geode\mods\elohmrow.death_tracker\levels`
   на Windows.
2. **Привязать уровень** — поиск по списку уровней мода (фильтрация по мере
   набора, стрелки по списку). Сеансы можно привязывать в момент создания.
3. Всё. Дальше смерти и раны попадают в журнал сами, с правильными
   стартпосами и временем.

Настройки под рукой: включить/выключить наблюдение, учитывать ли раны со
стартпосов, «только раны со стартпосов сеанса» — фильтр практики, потому что
мод не отличает практис-ран с чекпоинта от настоящего. Практика «с нуля»
отфильтровывается всегда. Если имена совпадают, сессия привяжется сама
(автопривязка).

Нюанс, о котором стоит знать: мод хранит итоговые счётчики, а не историю —
поэтому привязка фиксирует точку отсчёта, и дальше трекер берёт разницу
«текущее минус увиденное». Всё, что накапало в моде **до** привязки,
втягивается кнопкой «Импортировать всю историю» — счётчики разложатся в
записи `×N`. Если часть смертей случилась, пока трекер был закрыт, — не
страшно, при запуске он догонит и склеит их в одну запись.

И спокойствие за игру: во время гринда трекер опрашивает процессы раз в
20 секунд и пишет сейвы с паузой — кадры игре не отнимает. Если FPS всё
равно подёргивается, это почти наверняка антивирус —
[лечится исключением](#если-что-то-пошло-не-так).

### Заметки уровня

Правая колонка — свободный текст: планы, сложные места, что тренировать.
Автосохранение, счётчик символов. Заметки переживают всё: сброс статистики,
«Отменить», пересоздание частей — удаляются только вместе с самим сеансом.

### Blitzkrieg — тренировка кусками

![Blitzkrieg — стадии с чекбоксами галок](screenshots/blitzkrieg.png)

Панель под картой уровня — план тренировки «от кусков к фуллу». Из границ
частей строятся стадии:

- **Stage 1** — каждый кусок отдельно: `0–4`, `4–9`, `9–17` …
- **Stage 2** — куски из двух частей подряд: `0–9`, `4–17` …
- … и так, пока последняя стадия не станет всем уровнем `0–100`.

Ран закрывает галку, если покрыл её целиком: стартовал не позже начала
куска и доехал до его конца (смерть ровно на границе — доехал). Два режима
закрытия, переключатель в заголовке панели:

- **«По очереди»** — галки закрываются строго по порядку: одна попытка
  закрывает одну, следующую незакрытую. «Счастливый» ран 0–17% при частях
  0–4/4–9/9–17 закрывает именно `0–4`, а не прыгает вперёд.
- **«В любом порядке»** — внутри текущей стадии порядок не важен: тот же
  ран 0–17% закрывает сразу все три галки Stage 1 — `0–4`, `4–9` и `9–17`.
  Следующая стадия не трогается, пока текущая не закрыта целиком.

Режим глобальный и запоминается. Фулл 0–100% — исключение: он закрывает все
галки разом в любом режиме, из какой стадии бы они ни были. Прогресс нигде
не «вводится руками»: галки всегда выводятся из журнала попыток, тултип
ячейки показывает, каким раном она закрыта. Раскрыта всегда текущая стадия;
когда она закрывается, панель сама переходит к следующей.

### Сохранение сеанса в файл

![Окно экспорта сеанса в файл](screenshots/export-modal.png)

Кнопка «Сохранить сеанс в файл» (со стрелкой вниз) в панели ввода —
выгружает всю статистику сеанса одним файлом: `.txt`, `.md` или `.json`,
с живым предпросмотром, скачиванием и копированием в буфер. Имя файла —
`GD-Passrate-<уровень>-<дата>.<формат>`.

В отчёте всё: общий пассрейт и сравнение с моделями, средний и медианный на
часть, пассрейт каждой части, счётчики 50%+ … 80%+, стадия Blitzkrieg,
лучшие прогрессы и история рекордов, динамика по дням, время в игре, заметки.
Формат `.json` дополнительно содержит полный бэкап сеанса — по сути,
резервная копия, из которой всё восстанавливается. Работает и в браузерной
версии.

## Запуск в браузере

Быстро глянуть интерфейс без окна приложения:

```bash
npm run dev
```

Откроется `http://localhost:5173` — весь расчётный интерфейс: ввод, статистика,
карта, графики, импорт, экспорт. Чего в браузере нет — отслеживания запуска
игры и моста к Death Tracker: эти панели честно сообщат, что работают только
в приложении. Сессии, записанные в приложении, в браузере видны.

## Где хранятся данные

Вся статистика лежит в профиле приложения — **не** в папке с архивом, поэтому
переустановка и обновление трекера её не трогают:

| ОС | Папка |
|---|---|
| Windows | `%APPDATA%\gd-passrate-tracker\` (например `C:\Users\<имя>\AppData\Roaming\gd-passrate-tracker`) |
| macOS | `~/Library/Application Support/gd-passrate-tracker/` |
| Linux | `~/.config/gd-passrate-tracker/` |

Отсюда два практических следствия. **Перенос на другой компьютер** — просто
скопируй эту папку на новую машину по тому же пути, и вся статистика поедет
с тобой. **Начать с чистого листа** — закрой приложение и удали (или
переименуй) папку: трекер стартует пустым. Хочешь подстраховаться — периодически
жми «Сохранить сеанс в файл» с форматом `.json`: в этом файле лежит полный
бэкап, который можно импортировать обратно.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `npm install` падает на скачивании Electron | Повтори команду — докачает. Если GitHub недоступен: `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install` |
| `tsc: не является командой` | `npm install` не дошёл до конца. Прогони его заново и проверь `node -v` — версия 18 или новее |
| Странные ошибки про `math.ts` после обновления | Архив распакован **поверх старой версии** — распакуй в чистую пустую папку |
| Подёргивания FPS в игре во время гринда | Почти наверняка антивирус сканирует сейв мода на каждую смерть. Добавь папку `…/elohmrow.death_tracker/levels` в исключения проверки в реальном времени |
| Окно «зависает и исчезает» при развороте на весь экран | Исправлено в v1.13 — убедись, что версия не старше |
| Янтарный бейдж «Отслеживание приостановлено» | Опрос процессов заблокирован (обычно антивирус). Не критично — трекер работает, но запуск игры не видит: запусти от обычного пользователя и добавь исключение |
| `exited with signal SIGINT` в консоли | Это просто Ctrl+C — штатное закрытие, ничего не сломалось |

Если проблема не отсюда — приложи к вопросу версию трекера (она в имени
архива и в первой строке README) и текст ошибки из консоли при запуске.
